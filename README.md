# Furkan Akkaya — scientific portfolio

## Question

Can a small static portfolio present molecular biology, structural bioinformatics
and computational drug discovery projects with traceable evidence rather than
hand-written achievement claims?

## Approach

Plain HTML and CSS, generated by a Python standard-library script. No frontend
framework, client-side JavaScript, external fonts or runtime API calls.

The [30-repository inventory](data/repositories.json) defines P01–P30 in order.
`--refresh` reads sibling README files, extracts titles and questions, and admits
only repositories with Results and Limitations sections and no planned status.
The first numerical prose result containing a complete sentence is preferred to
table captions; the first results paragraph is the fallback. The first limitation
paragraph or list item accompanies every card. Negative results remain eligible.
P23 is explicitly deferred because its README says the atomistic EGFR profile is
not established; P27 excludes itself. The [inclusion audit](data/projects.json)
records a reason for all 30 decisions. This conservative rule also omits some
implemented tools that lack a Results section.

Each card links to its original README at a pinned Git commit and to a local
excerpt page with line references and the full README SHA-256. Markdown formatting
is removed; scientific claims are quoted, not composed by the generator. Refresh
rejects uncommitted source README edits. The committed snapshot makes CI independent
of access to the other repositories. See [scope and acceptance criteria](docs/SCOPE.md).

## Results

The recorded 24 October 2026 snapshot contains **16 cards from 30 inspected
repositories**, with **14 excluded** and **17 generated HTML pages**. Authenticated
GitHub reads verified **16/16 pinned README hashes and excerpt sets**; the
[verification record](docs/source-verification.json) stores the checked URLs and time.

- **34/34 pytest cases passed**: source attribution, selection boundaries,
  HTML structure, escaping, local links and fragments, stale-page removal,
  deterministic regeneration and the disabled deployment gate.
- Chromium rendered **17 pages × 2 viewports = 34 checks**, at **390 px** and
  **1440 px**. There were **0 horizontal overflows**, **0 HTTP errors** and
  **0 JavaScript page errors**.
- axe-core 4.10.3 reported **0 violations** in the selected WCAG A/AA and best-practice
  rules across those checks. Its **2 incomplete rule instances** concern the
  decorative, `aria-hidden` down arrow, once per viewport; its white-on-dark
  palette is covered by the [manual contrast calculation](docs/acceptance.json).
  Keyboard checks confirmed the visible skip link and focus outline at both widths.
- **2/2 screenshots** were captured and visually reviewed:
  [desktop](docs/screenshots/desktop.png) and [mobile](docs/screenshots/mobile.png).
  Detailed browser observations are in [the browser report](docs/browser-verification.json).

These are software and presentation checks. The source repositories' scientific
results were not independently reproduced for this portfolio.

## Reproduce

Python 3.11 or newer; run from the repository root:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
python scripts/build.py
pytest -q
python -m http.server 8000 --directory site --bind 127.0.0.1
```

Open `http://127.0.0.1:8000`. The generated `site/` directory is self-contained and
can also be opened as local files. Edit styles in `assets/style.css`, then rebuild.
Do not edit generated HTML directly. The build removes obsolete HTML files from
its output directory; use a directory reserved for generated files.

To refresh from the local repository collection and recheck remote attribution:

```bash
python scripts/build.py --refresh ..
python scripts/verify_sources.py
pytest -q
```

The second command requires authenticated `gh` access to the source repositories;
it performs reads only. Refresh is explicit, not scheduled. Review snapshot and
site diffs before committing.

Optional browser verification, using installed Chromium and Node/npm:

```bash
pip install -r requirements-browser.txt
npm install --prefix /tmp/p27-a11y --no-audit --no-fund axe-core@4.10.3
python scripts/check_browser.py \
  --axe /tmp/p27-a11y/node_modules/axe-core/axe.min.js \
  --chromium /usr/bin/google-chrome
```

## CI and deployment

[CI](.github/workflows/ci.yml) builds from the committed snapshot, runs pytest,
checks generated files against Git and uploads the site and test report. It runs
on main pushes and pull requests. Hosted results are available in
[GitHub Actions](https://github.com/Akkaya-Furkan/portfolio-site/actions/workflows/ci.yml).

The [Pages workflow](.github/workflows/pages.yml) is deliberately **inactive**:
it has only a manual trigger and `if: ${{ false }}` on the deployment job.
No Pages publication is performed. Enabling it requires a separately authorized
workflow change and repository Pages configuration. The repository remains private.

## Limitations

- This is a dated README snapshot, not an automatically updating GitHub API site.
  Other repositories can change after the recorded source commits.
- A Results heading is an evidence filter, not proof of project completeness or
  scientific validity. Only a selected result and limitation appear on a card;
  read the entire original README for context and all unimplemented work.
- Private source links require GitHub access. Remote existence was checked at
  delivery; future access, repository deletion and availability cannot be guaranteed.
- Automated accessibility rules and two widths do not constitute full WCAG
  certification, screen-reader testing or comprehensive device coverage.
- No hosted site, contact form, analytics, experimental validation or scientific
  rerun is included. Software-demo measurements are not biological observations.
